# CLAUDE.md

## Project
A playground for trying out Google Workspace/Drive APIs and PDF structural parsing. Two
independent tools live here:

1. **Directory/Drive web app** (`app.py`) — FastAPI app with "Sign in with Google" (OAuth2).
   Once logged in, a user can:
   - List all names/emails in the `aot-technologies.com` Workspace directory (People API,
     falls back to Admin SDK Directory API).
   - List the subfolders of a fixed Google Drive folder.
   - Cross-check directory users against Drive folder names by fuzzy name match (word-by-word
     similarity, not raw character sequence matching — see `name_similarity` in `app.py` for
     why: naive whole-string matching produced false positives on short names) — surfacing
     users with no matching folder, and folders with no matching active user.

2. **BCBC MO Package PDF indexer** (`src/bcbc_mo_index.py`) — parses
   `MO Package BCBC MRK signed.pdf` (a 1685-page merged BC Building Code + Ministerial Order
   package whose own PDF bookmarks are too coarse to use directly) into a full hierarchical
   index: Volume → Division → Part → Section → Subsection → Article → Sentence → Clause →
   Subclause, plus "Notes to Part" → Note, and a Table/Figure index. Heading detection relies
   on font metadata (`Arial-Black` for real headings, `Arial-BoldMT` for real Table/Figure
   captions) to reject citation references that merely wrap to the start of a line.

3. **bcbc_2024 PDF indexer** (`src/bcbc2024_index.py`) — same target index shape as the MO
   Package indexer, for `data/bcbc_2024.pdf` (1906 pages, a different production with its own
   font family and a real two-Volume split — Volume I / Volume II). Unlike the MO Package,
   this PDF's own bookmark outline (`doc.get_toc()`) is complete and reliable — it drives the
   whole Volume/Division/Part/Section/Subsection/Article/NotesContainer/Note/Appendix
   skeleton directly, by pattern-matching bookmark titles rather than page fonts. A second,
   font-based pass (this PDF's own `HelveticaLTStd-Blk`/`-Bold`/`-Roman`) still finds
   Sentence/Clause/Subclause and Table/Figure captions, neither of which the bookmarks cover.

4. **Figure image extractor** (`src/extract_figures.py`) — reads the Figure index already
   produced by `bcbc_mo_index.py` and, for each entry, locates and extracts its source raster
   image from `MO Package BCBC MRK signed.pdf`, for future visual similarity comparison.
   Confirmed by direct inspection: not every embedded image is a Figure (cover logos, inline
   body-text glyphs, and end-of-document permit-form graphics are filtered out by minimum
   on-page size), captions can appear either above or below their image, and an image can sit
   on the page before its caption's own page when the two straddle a page break — the matcher
   handles all three. Writes extracted images to `output/figures/`, plus
   `output/bcbc_mo_index_figures.json` (image path, pixel size, perceptual hash via
   `imagehash`) and `output/bcbc_mo_index_figures.md` (human-readable report with thumbnails).

A standalone CLI companion, `src/check_directory_access.py`, checks (outside the web app) 
whether a given account can list the Workspace directory via the People API vs. the Admin SDK,
and prints which path works and why.

## Folder structure
- `app.py` — the FastAPI app; stays in the project root (its own entry point).
- `src/` — every other Python script (`bcbc_mo_index.py`, `bcbc2024_index.py`,
  `extract_figures.py`, `check_directory_access.py`). All anchor their file paths
  (credentials, token, PDF, output) to the project root via
  `Path(__file__).resolve().parent.parent`, not the current working directory, so they run
  correctly regardless of where they're invoked from.
- `data/` — input source files, e.g. `MO Package BCBC MRK signed.pdf`, `bcbc_2024.pdf`.
- `output/` — everything a program run produces: `bcbc_mo_index.json`, `bcbc_mo_index.md`,
  `bcbc_mo_index_figures.json`/`.md`, `figures/` (extracted Figure images), and any future
  `.json`/`.md`/`.txt` result. Regenerated by re-running the producing script; safe to delete
  and rebuild.
- `ai_docs/` — Markdown written by Claude directly as part of analysis or solution-building
  (design notes, reports) — distinct from `output/`, which is only ever machine-generated by
  running a script.
- Root also holds: `credentials.json` / `token.json` (OAuth secrets — never commit these if
  this ever becomes a git repo), `requirements.txt`, `Readme.md`.

## Setup
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Run the web app (needs a Web-application-type OAuth client in Google Cloud Console with
redirect URI `http://localhost:8000/auth/callback`, downloaded as `credentials.json`):
```bash
export SESSION_SECRET=$(python -c "import secrets; print(secrets.token_hex(32))")
python -m uvicorn app:app --reload
```

Run the PDF indexers (from the project root) — each defaults to its own PDF in `data/`,
writes to `output/`; pass a path to index a different PDF instead:
```bash
python src/bcbc_mo_index.py
python src/bcbc_mo_index.py /path/to/other.pdf

python src/bcbc2024_index.py
python src/bcbc2024_index.py /path/to/other.pdf
```

Run the Figure image extractor (after `bcbc_mo_index.py` has produced its JSON):
```bash
python src/extract_figures.py
```

Run the directory-access CLI check (needs a Desktop-app-type OAuth client, separate
`credentials.json` from the web app's):
```bash
python src/check_directory_access.py
```

## Workflow
- TDD, strictly: failing test → minimum code to pass → refactor. Never weaken or delete an
  existing test to make a build pass.
- Always outline a step-by-step plan before making multi-file modifications.
- Fan out subagents for independent, context-heavy work (e.g. research, log searching, one
  agent per code section being changed).

## Code standards
- Clean Architecture + SOLID: keep domain/business logic (fuzzy matching, PDF structural
  classification) free of HTTP, OAuth, file I/O, and PDF-library specifics. Inject
  dependencies through small, role-specific interfaces rather than instantiating concrete
  classes inline.
- Functions ≤20 executable lines, cyclomatic complexity ≤6, nesting ≤2 levels. Guard clauses
  and early returns over nested `if/else`.
- Intent-revealing names. No speculative abstractions, unused wrappers, or phantom layers.
- Tests cover boundaries, empty/null, and expected exceptions — not just happy paths.

## Definition of done
Run these and fix everything they report before calling a task complete:

1. `ruff check --fix . && ruff format .`
2. `radon cc -s -n B .` — refactor anything graded C or worse
3. `vulture .`
4. `pytest --cov=.` — all green, new branches covered

Not yet wired up in this repo (no `pyproject.toml`/lint config, no test suite exists yet) —
apply this checklist as tooling and tests are actually introduced, not retroactively to
existing untested scripts.
